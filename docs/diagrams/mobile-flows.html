Mobile app — cloud session sync (M5) & offline transfer queue (M6)

Local-first by default; the account is used for resume-anywhere and background uploads

M5 · CROSS-DEVICE SESSION SYNC — “Continue from your account”

📱 Device A — read

Open a file (local or Drive). After 1.5 s debounce, syncSession() saves the reading session.

→

Server — account workspace

POST /api/workspaces/sync { key:"mobile-reader" } — last 5 tabs, resourceKey: drive:<fileId>, scroll position (PDF page rides in scrollTop).

→

Stored with the account

Per-user MongoDB-shaped record (§14 /api/workspaces), lastOpenedAt stamped.

→

📱 Device B — sign in

GET /api/workspaces → account session newer than device history? → Home shows the “Continue from your account” card.

→

✅ Resume anywhere

openCloudTemp() streams the file server-side → reader opens at the saved page/scroll. MOB-12 verified end-to-end.

The device stays fully usable with no account — signing in is optional (no login gate). Sync only stores references + positions, never file bytes.

M6 · OFFLINE UPLOAD QUEUE — honest states, auto-resume on reconnect

📱 Pick files → Review

Library → select → destination → Review upload. The review always states: existing Drive files are never overwritten.

→

Offline? Queue it OFFLINE

Confirm button becomes “Queue N file(s) for when online” — job lands in Activity with an honest Offline badge, never claimed as done.

→

Read locally meanwhile

Offline banner: “Drive transfers pause; local reading stays available.” Files stay readable from the offline copy.

→

Reconnect → auto-start

The online event re-runs queued uploadToDrive jobs (resumeQueued), then re-syncs the session.

→

✅ Completed COMPLETED

Badge flips to Completed; the file is really on Drive (verified by smoke). Retry-failed stays available for real errors.

Background-transfer scope on the web runtime: jobs keep running across screen switches and auto-start on reconnect; there is no OS-level background daemon in a PWA — this is the honest PRD §8 behavior.

M6 · DRIVE CHANGES CHECK — “what changed since my last check?”

⇅ Changes button

Drive tab header. Stores its page token locally (rsm.changesToken).

→

Changes API

GET /api/drive/changes?pageToken=… → real changes.list, or the mock per-user change log in sandbox.

→

✅ Honest note

“N file(s) changed since your last check — latest: X.” or “No changes since your last check.” New token stored for next time.
