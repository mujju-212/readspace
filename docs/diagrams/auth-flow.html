R

Google Drive connection — OAuth 2.0 + PKCE & token security

Same route shapes in both modes: real Google when credentials are set, built-in sandbox when not

REAL MODE — GOOGLE_CLIENT_ID + GOOGLE_CLIENT_SECRET set

1
App checks mode

GET /api/config → mode: "google"; Settings shows “Connect Google Drive”.

2
Start authorization

GET /api/auth/google/start?drive=1&returnTo=… — server generates PKCE code_verifier + S256 code_challenge, state and a secret-binding cookie.

3
User consents at Google

Google account chooser & Drive scope consent (openid, email, profile, drive).

4
Redirect back

GET /api/auth/google/callback?code&state — state + verifier cookie verified server-side.

5
Code exchange

Server POSTs code + client_id + client_secret + code_verifier → access + refresh tokens.

6
Identity + persistence

User verified from ID token; identity stored separately from the Drive authorization.

SANDBOX MODE — credentials unset (default)

1
App checks mode

GET /api/config → mode: "sandbox"; UI identical, badge says sandbox.

2
Start authorization

Same /api/auth/google/start — returns the in-app consent page instead of Google.

3
Mock consent form

/mock/google/consent — demo.user@gmail.com, “Allow” grants the same scopes against a mock Drive.

4
Redirect back

returnTo with ?signedin=1; same state checks as real mode.

5
Code exchange

Mock tokens — identical token shapes, so the rest of the app can’t tell the difference.

6
Identity + persistence

Fixed demo identity; seeded mock Drive (Papers, Study Notes, …) + per-user change log.

Both modes, steps 7–8:  7 — the refresh token is encrypted AES-256-GCM (v1:base64(iv|tag|ct), key from TOKEN_ENCRYPTION_KEY) and stored server-side only.  8 — a session cookie is issued; the frontend can only ever see GET /api/auth/me → { email, name }.
Token security guarantees (PRD §13): refresh tokens and client secrets never leave the server · every Drive read/upload runs server-side with the acting user’s own decrypted token (user derived from the verified session, never from the request body) · revoking the app in Google immediately breaks server calls and the UI reports honest “needs re-connect” state · rotating TOKEN_ENCRYPTION_KEY invalidates old ciphertexts (versioned v1: format).
